# Gate E/F (prospective)

PASS for implementation investigation, before runtime/outcomes. This is not an
empirical validation or adoption decision. Architecture and matrix committed
before implementation. Gates A/B/C independently passed; protected endpoint021.

1. Two disjoint commitments: registry max4, social cap2.
2. Independent unavailability: participant-owned reservations.
3. Different finish: exact scene-specific completion.
4. Same finish: deterministic scene IDs and release records.
5. Same tick: need → core scenes → claims → meals → releases → response/admission → choices.
6. Hunger once: absolute four-tick pulse, one global clock, opt-in query sync.
7. Transfers: existing core legality/accounting, separate actor components.
8. Competing invitations: independently scored recipient picks one.
9. Busy recipient: no response opportunity; admission rechecks availability.
10. Free acquisition: own claim reservation, independent from disjoint scene.
11. Inquiry: exclusive with physical work and pending deadlines; block audited.
12. Stale knowledge: one owned LastSeen slot, no remote depletion updates.
13. Reconstruction: primitive events, reservation transitions and causal IDs.
14. Compatibility: no protected source edits; all historical byte replay required.
15. Negative/null: registered scarce, private twins, order, null/exhaustion cases.

Critical risk: additive atomic-time hooks must cover actual query writes and remain
no-op in old worlds. Failure stops implementation rather than relaxing the contract.
