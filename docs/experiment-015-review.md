## Proposal, consent and arbitration

All three own inputs/proposals are captured before recipient responses. A proposer
sees its own Agent/profile, bounded own inquiry projection and current public room,
availability/horizon. A recipient sees only its own input/outgoing plan and actual
incoming sender/type/expiry. Proposal and response are replaceable pure functions.
No pair list scripts their choices. Public encounter ordinal affects old source
eligibility without revealing another person's private event payload.

Acceptance grants provisional permission for that incoming edge. It is not an
exclusive booking, withdrawal of an outgoing proposal, resource Accept or evidence
promise. An actor can accept incoming while retaining outgoing permission. Greedy
arbitration can execute the outgoing edge, displacing the incoming edge it accepted.
Every executed edge still has a real proposal and recipient Accept; no declined
recipient is compelled. This documented semantics is internally consistent, but
cannot be described as exclusive commitment or optimum preference satisfaction.

Requests expire exactly at the response/arbitration tick. Reciprocal same-kind
requests produce one execution and one Reciprocal classification. Other accepted
edges sharing a participant become Contention. No two incompatible encounters
execute. Prior public unavailability excludes proposals; a lost/expired request
cannot later execute. Three people imply all pairs overlap; serial resolution is
valid within this platform, not a general concurrent scheduler.
